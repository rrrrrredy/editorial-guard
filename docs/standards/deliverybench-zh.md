# DeliveryBench-ZH：中文交付阶段标准

许可：CC BY 4.0。协议版本：0.1.0。

任务是清除当前交付位置不需要的写作、编辑、协作和执行旁白。判据是任务、阶段、渠道和上下文；不是删除所有提到过程的句子。

|类别|应复核的例子|必须保留的边界|
|---|---|---|
|结构预告|成稿前的“下面我先分析”|用户要求的计划或教学安排|
|自我评价|“以下是深入且可落地的版本”|有证据的研究质量分析|
|编辑残留|正文里的内部待办、版本讨论|用户明确要求展示修改意见|
|协作包装|把交接备注贴入公开正文|工作进展与必要失败通知|
|额外结尾|正文后附“我已为你去除AI味”|用户要求的编辑说明|

同一句“我先核对资料，再给出结论”，在计划中可以适用，在仅要最终结论的正文中可能不适用。未完成、权限、失败、风险与不确定性不能被清理成已完成。研究方法、复现步骤、推导、操作说明、代码注释与引文按任务保护。

严重度：1为一处可忽略包装；2为反复旁白影响阅读；3为内部残留显著妨碍直接使用；4为交付位置基本被错误阶段内容占据。分类pass/fail优先，严重度只描述问题程度。

报告文档级precision/recall/F1、片段级定位、清除率、必要内容误删、阶段判断、无问题放行、实际交付残留。Unicode code point半开区间[start,end)，不归一化，重复片段按出现序号定位。无预测时precision未定义，无正例时recall未定义；F1分母为0时为null，并报告原始计数。

通过模型调用不等于交付通过。调用失败、格式错误、截断、弃权和内容失败分别保留；报告成功响应条件下能力及包含全部登记任务的端到端结果。
