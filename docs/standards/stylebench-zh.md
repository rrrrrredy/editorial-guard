# StyleBench-ZH：中文文风问题标准

许可：CC BY 4.0。协议版本：0.1.0。正式目标为简体中文原生任务，中文技术混排保留。本文是规范；已验证范围须以相应版本实验报告为准。

文风问题是相对任务、读者和作者风格的不适配表达。评测不鉴定作者是否为AI，不以逃避检测为目标。每个问题必须定位原文、说明语义作用和适用规则；形式匹配只能触发复核。

|维度|0|1|2|3|4|
|---|---|---|---|---|---|
|模板依赖|表达由内容决定|一处可删的套语|多处同类套语，核心信息仍清楚|多数段落被同一结构牵引|主体几乎都是模板，无从辨认具体判断|
|信息表达效率|每段有必要信息|局部同义重复|反复转承或抽象词降低密度|大量文字无信息增量，关键条件难找|信息基本被空泛评价淹没|
|行文连贯性|论据、关系与段落自然衔接|一处可调整的跳转|多处重复或割裂但关系可恢复|结构显著妨碍跟随论证|主要论证无法恢复|
|场景/风格匹配|符合文体和读者|轻微不合适的语气|反复不合场景的措辞|整体语气与任务明显冲突|表达方式使交付物基本不能使用|

严重度的跨维例子：0“试验组用电较少，但两组负荷不同，不能据此认定效率提高”；1在完整段落后重复一句“这一点值得关注”；2每段都追加无信息总结；3多数篇幅用“赋能、闭环、重塑”代替给定事实；4只有这些口号，事实、条件与论证均无法辨认。等级不是词频阈值，主观边界保留分歧。

正向边界：真实三个并列对象可以列三项；“不是已支出，而是预算”纠正概念误读，应保留；教程短段和必要标题不自动扣分。反例：“真是绝了，我亲自用过”在无体验资料时既可能场景不适配，也构成内容增写，后者直接阻止编辑成功。

相对改进用 better/tie/worse/uncertain，允许不同合格改写。四维分别报告；不与DeliveryBench相加为总AI味分数。过程问题归process，不能因删除同一句旁白在两个总分中重复奖励。主实验提示裁判排除过程影响，但这不等于已经逐字遮蔽输入；实际字面遮蔽结果作为单独的补充分析报告。

有效修改须同时满足目标改善、关键信息保留、任务要求满足、无严重新问题。空输出、过度摘要、拒绝编辑或固定模板不能通过；无需修改文本可原样保留。主观判断是模型判断，未经人工验证。

## 分维度锚点与反例

以下短片段说明同一维度内的边界，完整评分仍须检查上下文。每行的反例说明为什么相似形式未必应得该档；不能靠词表自动定级。

|维度/严重度|该档示例|不应据此判为该档的反例|
|---|---|---|
|模板依赖0|“预算尚未支出，采购须等两组测试通过。”|出现“不是已支出，而是预算”是在澄清概念，不是模板问题。|
|模板依赖1|完整说明后多一句“这一点值得关注”。|结尾说明“下次复核仍需检查第二组”有新增行动信息。|
|模板依赖2|每段均以“从这一角度看”起头，但事实仍清楚。|平行列出三台设备的三个不同故障，结构相同有功能。|
|模板依赖3|大多数段落先“打破旧局、重塑未来”，事实只能在夹缝里找到。|年度报告统一列出每季度数字，不因结构统一扣高分。|
|模板依赖4|整篇只有“以创新为引领、以协同为支撑”等重复骨架。|题目明确要求列口号时，先按该任务评价，不强套说明文。|
|信息表达效率0|“两组负荷不同，不能据用电差认定效率提高。”|必要限定增加长度，仍有信息作用。|
|信息表达效率1|“尚未支出，也就是还没有花出去”在非教学语境中局部重复。|面向儿童解释术语时，同义解释可能必要。|
|信息表达效率2|三段反复解释“发运不等于签收”，其余内容完整可找。|每次解释对应不同责任主体或时间节点时可能有新增信息。|
|信息表达效率3|多数篇幅赞扬工作，预算、条件和未知项难以定位。|材料本身复杂而篇幅长，不代表效率低。|
|信息表达效率4|只有“持续推进、取得成效、意义重大”，无法找到必要事实。|摘要短却遗漏限制，同样不合格，不能作为优秀表达对照。|
|行文连贯性0|先说明结果，再给条件和证据边界。|教程按操作顺序叙述也可连贯，不强求结论先行。|
|行文连贯性1|同一指代晚一两句才解释，局部回读即可恢复。|首次出现的专业名词紧随定义，不应仅因术语扣分。|
|行文连贯性2|多次在预算和测试间跳转，关系仍可恢复。|预算变化与测试进度交替对应时，交叉叙述有因果功能。|
|行文连贯性3|条件分散在互不关联的小节，主要推理需要反复拼接。|必要的表格索引或交叉引用不自动等于割裂。|
|行文连贯性4|无法确定谁做了什么、结论依据何在；段落关系不可恢复。|原资料确有矛盾时须指出信息问题，不能全归文风。|
|场景匹配0|工作报告写“第二组尚未通过，采购条件未满足”。|社交短文中适量口语可合适，不要求统一公文腔。|
|场景匹配1|正式报告偶有一句“这事得盯着点”。|内部熟悉同事的提醒邮件可能恰当。|
|场景匹配2|技术说明反复用夸张感叹替代读者需要的条件解释。|营销任务中的适度感叹不等于技术说明的错误。|
|场景匹配3|正式交付整体变成聊天式表态，操作与限制难以使用。|用户明确要求访谈口吻时，不能按公文扣分。|
|场景匹配4|把严肃方法说明写成无法使用的戏谑独白。|创作任务允许角色独白；虚构亲历若被当事实仍由保真门槛阻止。|

上述例子均为本项目构造的解释性锚点，不是人工标注结果或已证明等距的测量尺度。0—4 属于有序等级，均值不能抹去分歧或严重事实错误。
